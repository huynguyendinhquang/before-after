## Working guidelines

Follow the Karpathy guidelines:

1. **Think before coding.** State assumptions, surface uncertainty and trade-offs, and ask when the requirement is ambiguous.
2. **Prefer the simplest solution.** Build only what is requested; avoid speculative features, unnecessary abstractions, and avoidable dependencies.
3. **Make surgical changes.** Touch only what the task requires, preserve existing conventions, and clean up only artifacts introduced by the change.
4. **Work toward verifiable goals.** Define success criteria before implementation and verify the result with the smallest relevant check.
